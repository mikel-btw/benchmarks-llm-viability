LLM Viability Benchmark

Sistema de benchmarking empírico para evaluar la viabilidad de ejecutar modelos de lenguaje de gran escala (LLMs) localmente en hardware modesto.

¿Qué es este proyecto?

Este proyecto es un sistema de evaluación automática y manual de LLMs ejecutados localmente a través de Ollama. Fue desarrollado como base experimental de un artículo de investigación académica del CIAI (Centro de Inteligencia Artificial e Innovación, Colombia).

El sistema mide dos dimensiones para cada modelo y máquina evaluados: la velocidad de inferencia (qué tan rápido responde el modelo) y la calidad de sus respuestas (qué tan correcto e inteligente es lo que produce).

Un resultado pobre es tan válido como uno exitoso. Si un modelo es demasiado lento o no puede correr en una máquina modesta, eso es un hallazgo experimental, no un fracaso.

Objetivo de investigación

Determinar empíricamente si alguna combinación de modelo y hardware produce resultados suficientemente rápidos e inteligentes para ser utilizable en la práctica.

Pregunta de investigación

¿Cómo cambia la relación entre rendimiento inferencial y calidad de respuesta al ejecutar LLMs localmente en hardware modesto frente a hardware de laboratorio?

La pregunta definitiva se formulará después del análisis de los datos experimentales. El proyecto no parte de una hipótesis sobre el resultado esperado.

Áreas de análisis

  • Velocidad de inferencia vs. calidad de respuesta
  • Conocimiento general y razonamiento
  • Razonamiento matemático
  • Coherencia y seguimiento de instrucciones
  • Comportamiento en hardware con recursos limitados

Cómo funciona

El sistema es una aplicación de línea de comandos que guía al investigador a través de la selección de máquina, modelo y benchmark.

Flujo de ejecución

  1. Verificación de Ollama. Al iniciar, el sistema llama a ollama.list(). Si el servidor no responde, imprime instrucciones para correr ollama serve y termina.
  2. Selección de hardware. El usuario elige cuál de las 4 máquinas está usando en esta sesión.
  3. Selección de modelo. Se listan los 14 modelos disponibles agrupados por tier. El usuario elige uno.
  4. Selección de benchmark. Se presenta el menú de categorías. El usuario elige qué evaluar.
  5. Ejecución y guardado. El benchmark corre, las métricas se miden y el resultado se guarda en results/ como JSON.

Menú de benchmarks

[2] HellaSwag (DeepEval)
[3] TruthfulQA (DeepEval)

[5] Correr todos

Stack tecnológico

Todo corre localmente. No se usa ninguna API externa ni clave de nube.

Dependencias principales

LibreríaUso
ollamaCliente Python para comunicarse con el servidor Ollama local
deepevalFramework de benchmarking con datasets estandarizados (MMLU, HellaSwag, TruthfulQA)
psutilMedición de uso de RAM durante la inferencia
pandasProcesamiento de resultados
matplotlibGeneración de gráficas

Entorno de inferencia

  • Runtime principal: Ollama
  • Runtime secundario para comparación: vLLM
  • Interfaz visual: Open WebUI via Docker + Portainer

Integración con deepeval

deepeval no soporta Ollama nativamente. Se implementó la clase OllamaDeepEvalLLM que hereda de DeepEvalBaseLLM y redirige las llamadas de deepeval al cliente local de Ollama. Esto permite usar los datasets estandarizados de deepeval sin ninguna API externa.

Categorías de evaluación

El sistema tiene dos tipos de benchmarks: automatizados via deepeval y manuales con scoring del investigador.

Benchmarks automatizados (deepeval)

MMLU — Massive Multitask Language Understanding

Evalúa conocimiento general en 57 categorías académicas y profesionales. Se corren 10 preguntas por subtarea. El scoring es automático.

HellaSwag

Evalúa razonamiento de sentido común y completación de oraciones. 10 preguntas por subtarea.

TruthfulQA

Evalúa precisión factual y resistencia a falsedades comunes. 10 preguntas por subtarea.

Benchmark manual

Prompt Qualification

10 prompts en español que evalúan seguimiento de instrucciones, resumen, razonamiento lógico, problemas matemáticos, conocimiento factual, seguimiento de roles, code-switching técnico inglés/español, manejo de preguntas ambiguas, respuesta estructurada y concisión.

El investigador revisa cada respuesta y asigna un score:

ScoreSignificado
1.0Respuesta correcta
0.7Parcialmente correcta
0.5Mínimamente correcta
0.0Incorrecta

Benchmarks no disponibles en producción: GSM8K y ARC Challenge fueron removidos del sistema. Ambos fallan por un bug interno de deepeval 4.2.3 que usa URIs incompletas de HuggingFace (gsm8k en lugar de openai/gsm8k, ai2_arc en lugar de allenai/ai2_arc). No existe versión compatible que corrija esto para Python 3.14 al momento del desarrollo.

Instalación del sistema

Guía para instalar Ollama, los modelos y el sistema de benchmarking en Linux y macOS.

1. Instalar Ollama

Linux

curl -fsSL https://ollama.com/install.sh | sh

macOS

Descarga el instalador desde ollama.com/download/mac o instala via Homebrew:

brew install ollama

Verifica que Ollama esté corriendo:

ollama serve

2. Descargar los modelos

Elige el comando según tu hardware. Si tu máquina tiene menos de 8 GB de RAM o es un equipo de uso cotidiano, usa los 9 modelos modestos. Si tienes hardware de laboratorio con 32 GB o más, descarga los 14 modelos.

Hardware modesto — MacBook Pro 2012 / Lenovo IdeaPad L340 (9 modelos)

ollama pull qwen2.5:0.5b && \
ollama pull qwen3.5:0.8b && \
ollama pull llama3.2:1b && \
ollama pull tinyllama:1.1b && \
ollama pull deepseek-r1:1.5b && \
ollama pull gemma2:2b && \
ollama pull llama3.2:3b && \
ollama pull qwen2.5:1.5b && \
ollama pull phi4-mini:3.8b

Hardware de laboratorio — iMac 2017 / Dell Precision (todos los modelos)

Primero descarga los 9 modelos modestos (comando de arriba), luego agrega los modelos de laboratorio:

ollama pull VIDRAFT/pocket-26b && \
ollama pull ministral-3:8b && \
ollama pull gemma3:12b && \
ollama pull deepseek-r1-distill-qwen:14b && \
ollama pull qwen3:30b-a3b-q4_K_M

3. Clonar el repositorio

git clone https://github.com/mikel-btw/benchmarks-llm-viability.git
cd benchmarks-llm-viability

4. Crear el entorno virtual e instalar dependencias

Linux

python3 -m venv venv
source venv/bin/activate
pip install -e .

macOS

python3 -m venv venv
source venv/bin/activate
pip install -e .

5. Ejecutar el sistema

Asegúrate de que Ollama esté corriendo antes de iniciar:

ollama serve

En otra terminal, con el entorno virtual activado:

python3 src/benchmarkcli.py

6. Correr los tests

pytest tests/

Limitaciones conocidas

Limitaciones técnicas identificadas durante el desarrollo del sistema.

GSM8K y ARC Challenge — removidos de producción

Estos dos benchmarks no están disponibles en el sistema. deepeval 4.2.3 los referencia con URIs incompletas de HuggingFace: gsm8k en lugar de openai/gsm8k y ai2_arc en lugar de allenai/ai2_arc. No existe versión compatible con Python 3.14 que corrija este bug al momento del desarrollo.

Requiere Ollama activo

El sistema no puede iniciar ni reiniciar el daemon de Ollama. Si ollama serve no está corriendo antes de ejecutar el CLI, la aplicación termina con error.

Primera ejecución requiere internet

Los datasets de deepeval se descargan de HuggingFace en la primera ejecución y se cachean localmente. Las ejecuciones posteriores no requieren conexión.

Scoring manual requiere presencia del investigador

Prompt Qualification no puede automatizarse. El investigador debe revisar cada respuesta y asignar el score durante la ejecución.

Modelos grandes en hardware modesto

Los modelos del tier de laboratorio (pocket-26b, gemma3:12b, etc.) fallarán o experimentarán swap extremo en el MacBook Pro 2012 y el Lenovo IdeaPad L340. Estos casos se documentan como resultados experimentales válidos.
